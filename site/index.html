Postmen

API workbench, full stack

A Postman-style workbench for testing APIs. Sign in, send any request, read the formatted response, and come back to your history later.

API testing was spread across tools, so auth and request history were hard to keep hold of. Postmen puts the request builder, formatted responses, saved history and usage stats in one signed-in dashboard.

It started as a MERN build with a separate Express server and a Vite client, then was rebuilt as one Next.js app whose route handlers talk to MongoDB directly.

Open postmen.vercel.app Read the code

Key

  1. 1InterfaceNext.js 15 App Router, React 19, Tailwind CSS 4, Radix UI
  2. 2ServerRoute handlers for auth, requests, history and stats
  3. 3AuthJWT with refresh, bcrypt-hashed passwords, Google sign-in
  4. 4DataMongoDB Atlas through Mongoose: users and request history

Tested end to end with Playwright. Hosted on Vercel.

PlateMate

Counter app, offline PWA

A meal-pass counter for a buffet. The owner adds a customer, sells a plan and ticks off a meal at each visit. It runs on the owner's phone and keeps working with the internet off.

The README puts it plainly: It counts meals, not money. Payment happens at the counter, so the app holds no prices at all.

Version 1.0 closed a double charge: a quick double tap on Start plan credited a plan twice for one payment. Every write now passes a guard that flips synchronously. In 1.1 the list lost its Use 1 buttons, because a stray thumb while scrolling could take someone's meal.

Backups export the whole database as one JSON file, and restores are all or nothing on purpose.

Read the code Read the owner's guide

Key

  1. 1InterfaceReact 19, Mantine, React Router, installable PWA
  2. 2DeviceCamera QR scanning, QR passes saved as images
  3. 3RulesOne data layer with no React: credits, customers, plans, backup
  4. 4DataIndexedDB through Dexie, on the phone. There is no server.

Tested with Vitest against fake-indexeddb. Runs from any static host.

Harbour Ride

Booking prototype, maps and email

A taxi booking site for Sydney. Riders see a fare on a real route before they book, and each booking lands in the operator's inbox with a reference number.

The server prices every quote and gives it an expiry, so the fare a rider books is the fare they were shown. A quote can be booked only once, which stops a double submit from creating two bookings.

If address lookup fails, the estimate falls back to a demo route instead of blocking the form.

Read the code

Key

  1. 1InterfaceReact on Vite, Radix Select, a date picker that loads only when needed
  2. 2MapLeaflet with OpenStreetMap tiles and the route drawn as a line
  3. 3ServerExpress API: geocoding with Nominatim, routing with OSRM, fare quotes
  4. 4MailNodemailer sends each booking with its reference

Quotes expire after 15 minutes, and each one can be booked once.

General notes

How I work, each with the file or commit that shows it.

  1. Keep the rules in one place.

    PlateMate's balance rules live in one data layer with no React in it, and the tests run against that layer directly.

    client/src/db

  2. Close the expensive mistake in code.

    A double tap once credited a plan twice, and a stray thumb in the list could spend a meal. Writes now pass a guard that flips synchronously, and list rows no longer spend.

    commit a350445

  3. Treat names as identities.

    The database is still called buffet-pass after the app was renamed. Renaming it would have orphaned every record already on the phone.

    db/schema.js

  4. Test the paths people depend on.

    Postmen has end-to-end tests for the landing page, sign-in and the dashboard, the three places a broken release would hurt most.

    tests/

  5. Rebuild when the shape changes.

    Postmen began as an Express server plus a Vite client. It became a single Next.js app, and the old folders went in one commit.

    commit 927d209

  6. Write for the person using it.

    PlateMate ships with an owner's guide in plain words: where to tap, what the green confirmation means, and how to back up.

    docs/OWNER-GUIDE.md
